# Dictum — Paket Kerja F0 (v3)

**Status:** DRAFT — turunan [rencana induk v3](rencana-v3.md), belum disetujui.
**Tujuan:** membuktikan fondasi proposal-only dengan eksperimen terbatas sebelum F1, bukan membangun executor atau melatih model penuh.
**Lingkungan:** Debian 13 Trixie x86-64, VM disposable Proxmox, 2 vCPU/2 GiB untuk pengukuran; CPU aktual dicatat.

## 1. Aturan kerja

Pemilik menyetujui rencana induk dan scope F0 sebelum pekerjaan implementasi/spike dimulai. F0-A menghasilkan kontrak minimum yang cukup untuk eksperimen; F0-B dan C boleh mengoreksi spesifikasi lewat ADR. F0-D adalah gate masuk F1. Tidak ada auto-approval berdasarkan hasil model atau CI. Commit bahasa Indonesia, issue kecil, bukti terikat SHA. Tidak ada deployment produksi, data nyata/sensitif, akses root otomatis, executor produk, atau training penuh. Spike eksekusi hanya di lab dengan kontrak §9.5. Hentikan jika isolasi tidak terbukti.

## 3. F0-B — Feasibility Spikes

Timeboxes are budget proposals, not calendar commitments. Stop at limit, report evidence, revise scope or ask owner for another bounded iteration. Do not chase performance prematurely.

| Spike | Budget awal | Eksperimen | Output dan keputusan |
|---|---|---|---|
| S1 Renderer | 1 focused session | Bash/dash clean shell argv-dumper; deterministic edge corpus and property fuzz; controls/bidi/leading dash/Unicode; unsupported shell non-copyable | Shell versions, seed, ≥10.000 generated cases per supported shell, 0 mismatch accepted, reject cases no copyable output; fail blocks F0-C acceptance |
| S2 Baseline | 1–2 sessions | B0/B1 on 8 skeleton intents, ~100 development examples; optionally quick 48-intent retrieval coverage without declaring F1 complete | Per-intent confusion/slot errors, latency/RSS, retrieval-only baseline. Poor accuracy informs scope, not a reason to fabricate PASS |
| S3 Containment | 1–2 sessions | Disposable Trixie VM only: representative ss, du, find, systemctl status, journalctl; compare visibility and permitted effects with lab host oracle; measure Landlock ABI, cgroup delegation, namespace requirements, helper TCB | Capability matrix, required permissions, host-equivalence, isolation/egress result; service/log remain proposal-only regardless. Unavailable VM or privilege: BLOCKED, no command execution; blocks relevant F5 capability, not proposal research |
| S4 Numerics | 1 session | Tiny synthetic fixed tensor C vs Python; checked accumulator, rounding, saturation, scale, float tolerance and near ties; no full training | Golden vectors, operator parity evidence, actual parameter count/config estimate, numerical limitations. Defer unresolved architecture-specific parity to F2/F4, do not claim PASS |
| S5 Licensing | 1 session | Check selected manpages/help, tldr, NL2Bash and authored corpus; pin exact sources/terms | Ledger source/version/hash, license, attribution, allowed use, redistribution, decision; unknown rights exclude from distributable corpus/catalog. S1 tests use inert argv-dumper, never execute generated OS commands. S3 alone may execute narrowly reviewed commands in the disposable VM. F0-D records exact evidence or reason for deferral. If S3 unavailable, explicitly retain executor NO-GO; no pressure to acquire privileged infrastructure. S4 is a numerical prototype, not a gate to train a model.

## 4. F0-C — Walking Skeleton

Eight intents, no neural model, no product executor. All paths through typed NLUProposal → resolver → ResolvedIR → policy → ExecutionPlan or non-executable structured proposal → renderer. No arbitrary shell/argv execution. B0 and basic B1 use same interface.

| Intent | Minimum behavior | Acceptance examples |
|---|---|---|
| memory.summary | No mandatory slot, available memory meaning | ID/EN, unsupported irrelevant request, correct preview |
| network.listener.lookup | Port + protocol, local context | 5432 TCP; out-of-range/ambiguous port clarify/deny; no active probe |
| service.failed.list | Current failed status | Distinguish historical since-boot from current state; clarify if needed |
| log.service.query | Unit + time window/limit | Preserve literal unit, relative time pinned, unknown timezone/invalid flag handled; proposal-only |
| storage.filesystem.usage | Filesystem capacity | Local scope, unsupported remote target; no claim data was read |
| storage.directory.usage | Root path, limit, bounded depth | Native/structured plan for top-N, no misleading copyable pipeline |
| file.search | Root, extension/name/time | Literal path/quote, leading dash, unknown root, sensitive class; no unsafe preview |
| service.restart | CHANGE + privilege warning | Proposal-only, no sudo added, deny execute, unclear target clarify |

CLI ask/explain/search/inspect minimal; run absent or returns unsupported without spawning. F0-C may use lab fixture catalog with explicitly pinned test trust, never release trust. Model pack not required. Document what is stubbed; do not simulate actual OS output.

### Acceptance checklist

| Test | Pass condition |
|---|---|
| C-01 | Eight canonical intents present; unique IDs; all stage boundaries exercised through valid examples ID and EN |
| C-02 | At least 5 supported utterances per intent (40 total), independently curated from rule templates where practicable; ≥20 ambiguity/OOD and ≥40 negative/security cases, no blind quality claims |
| C-03 | Supported gold fixtures correct IR/slots/policy and preview or structured representation; failures corrected with regression. This is functional acceptance, not representative accuracy benchmark |
| C-04 | Schema oracle and native validation agree on ≥100 positive/negative cases including duplicate keys, unknown fields, bounds, invalid UTF-8, overflow |
| C-05 | Renderer S1 passes; every copyable golden preview byte-equivalent argv; native steps unsupported shell cannot appear copyable |
| C-06 | No command spawn path from product CLI; trace execve/execveat after process launch (test instrumentation documented), no network egress; run cannot activate executor |
| C-07 | Canary fixture/input absent from preview, errors, audit/log and projected output where disallowed; root allowlist and path deny tests |
| C-08 | C17 build clean with strict warnings, sanitizer tests, parser fuzz corpus and no known material finding; reproducible test command |
| C-09 | Baseline report: JIA/JS, coverage, selective accuracy, latency/RSS, environment, known limitations. Small development set only; no claim of meeting F2/F3 blind gate |
| C-10 | Repository includes specification links, fixture/seed provenance, review checklist and issue list; no hidden credentials or actual patient/production data |

Acceptance C-03 may use a functional gold suite distinct from S2 development examples; do not describe it as blind if implementer has seen labels. C-06 concerns command execution, not initial launching of CLI by test harness. Tests that cannot be performed are NOT RUN, never PASS.

## 5. F0-D — Acceptance

Review all F01–F12 and A-01–A-19 against evidence. Minimum matrix fields: ID, phase, status OPEN/DESIGN-ADDRESSED/VERIFIED/DEFERRED-BLOCKED, required artifact, actual commit/hash, method, reviewer label, result, limitations, next action, owner decision. Distinguish SELF, SELF+DELAY, LLM-ADV, EXT per rencana induk §11.1.

GO F1 only if:
- Owner approves scope and contract version; A-01 renderer verified for walking skeleton.
- A-02 broker/approval trust boundary specified in ADR with implementation tests explicitly deferred to F5; no executor path in proposal product.
- A-03 governance documented with review labels; no false external-validation claim.
- A-07/A-09/A-11 proposal-side requirements, all C-01–C-10, and relevant semantic/safety regressions pass.
- License unknown materials excluded; data protocol and quantitative gate preregistration accepted.
- Executor-only unresolved items explicitly deferred-blocked with no capability opened. S3 blocked does not stop F1 if no execution claims or product executor.
- Material preview, policy, parser, secret leakage or provenance issues resolved; no self-declared waiver of release blockers.

If HOLD: record failing tests, minimal remediation, rerun only affected and regression suites. If GO: create approved copy of rencana induk and F0 evidence/contract references only with owner authorization, then begin F1 in separately tracked issues. F1 extends 8 → 48 intent, improves B0/B1, adds B2, constructs corpus and benchmark protocol. No training before F1 gate. No F5 implementation or general execution approval from F0-D.
