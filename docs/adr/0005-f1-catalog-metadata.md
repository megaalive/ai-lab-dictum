# ADR 0005 — Separate registry metadata from pipeline support

Ref #29 / #28. Decision: generate an exact-ID read-only metadata index for all 48 canonical intents from the existing pinned catalog/profile. This is not a capability table for runtime dispatch; existing eight synthetic B0/B1 rules remain the only compiled proposal recipes. Preserve F0-C source pins and user-visible proposal behavior. No utility commands, external documentation, host facts, runtime file access, new privileges, actual Debian validation, or scope expansion.

Search keeps existing intent/id/en keys; includes catalog eligibility as descriptive contract metadata and pipeline_status, blocked/unverified capability/version/compatibility, typed/deferred counts, explicit false execution/copyability/observed OS. Inspect retains legacy intent_count=implemented synthetic count and reports distinct catalogued/implemented/verified counts. Unknown IDs fail closed with fixed error; no echo. Exact lookup is not fuzzy NLU. Build fails on registry/profile drift or an opened binding. Independent Python source oracle checks all 48 actual CLI results, 13 invalid lookup cases, 40 unimplemented ID ask requests, and inspect; isolated CLI trace extends original 150 launches by 49. Tests pending until actual CI completes. Typed contracts and generalization follow separately; no F1 acceptance inferred.
