## Collect and review once

Collect 200–500 original human-authored examples in a private location outside Git, covering 48 canonical supported intent IDs, both Indonesian and English, ambiguity/OOD/security and near-miss families. Human author should see intent semantics and synthetic scope but not existing regression texts or grammar templates. Record author and distinct human reviewer pseudonyms, actual decision references and evidence digests; resolve disagreements before acceptance. Owner must actually approve exact source content and development fit/evaluation rights. Do not distribute, use external unverified text, upload private labels, or mix blind records. Target 70/30 ID/EN (mixed separate), no forced quotas after seeing results.

The seed JSON is an object with schema_version 1, role PRIVATE-HUMAN-DEVELOPMENT-SEED, and records. See `tools/f1_seed.py` RECORD_KEYS and `tests/research/f1_seed.py` for mechanical shape examples ONLY. Human roles are HUMAN-DEVELOPMENT-SEED / HUMAN-AUTHORED, and the reviewer must truly be a different person from the author. Supply text_sha256 of exact UTF-8 bytes and normalized_sha256 of grouping-only NFKC/casefold/space normalization. Supported expected labels have decision, reason, state, intent and typed resolved slots; slot_sources specifies input-span with byte offsets, context-ref with minutes-token span, or catalog-default. Negative gold uses exact oracle outcome/reason/state/intent, plus unresolved/alternatives for clarify. See resolved IR v2, canonical fixture, corpus protocol and original semantic contract; review semantic meaning, negation, target, units, scope and risk independently. Do not copy labels from native output. Risk tags NET/CHANGE reflect catalog effects. Source ID/version and attribution must correspond to the actual contributor and rights record.

Private rights JSON: schema_version 1, role OWNER-APPROVED-DEVELOPMENT-SOURCES, seed_sha256 (exact file bytes), owner_decision_ref, sources with id/version/record_set_sha256/origin ORIGINAL-HUMAN-CONTRIBUTION/rights_decision_ref/attribution; allow_development_fit and allow_development_evaluation true only after actual approval, allow_distribution and blind false. The per-source record-set digest is SHA-256 of canonical sorted JSON pairs [record ID, SHA-256 of canonical complete record], computed by source_digest() in f1_seed.py; canonical JSON uses sorted keys, UTF-8 and compact separators. Never generate an affirmative rights or review record automatically. Reviewer evidence and decisions are verified by people; the program only validates shape/pins.

## Candidate split, no fitting

On the exact reviewed source checkout (Python with existing jsonschema dependency):
```sh
python3 -B tools/f1_seed.py --seed /private/seed.json --rights /private/rights.json --output /private/candidate.json
```

This validates closed shapes, exact source/record identities, full supported class coverage, typed fixture slot bounds/defaults/byte provenance, review record shape, known regression/S2 normalized/fuzzy contamination, parent/semantic/family/fuzzy connected groups, deterministic 70/15/15 assignment and class/language counts. The manifest is PRIVATE-SPLIT-CANDIDATE, not an approved lock. It contains opaque IDs/hashes and fuzzy pairs only; actual identity, rights, language and semantics still require human evidence. Automated fuzzy detection is not proof of absence of leakage. Algorithm f1-group-v2-train-reservation first reserves whole connected components for every available supported training class, then balances the remaining components. The grouping is conservative: same canonical resolved label/fixture can collapse slotless paraphrases to one component; dev/test may not cover every class. The old v1 toy mechanics remain unchanged; no actual split had been locked. Report deficits; never break groups to manufacture coverage. If training has missing classes or dev/test are empty, do not fit; revise seed/scenarios before a new lock, not after benchmark results. No augmentations or blind input. F1 actual gold, evaluation and F2 decision remain separate.

Review the candidate once. An owner-reviewed lock JSON supplied from outside Git has fields defined in `tools/f1_compare.py` LOCK_KEYS: schema_version=1; role=OWNER-REVIEWED-F1-DEVELOPMENT-LOCK; scope=F1-B2-DEVELOPMENT-ONLY; candidate_manifest_sha256, seed_sha256, rights_sha256; owner_decision_ref, reviewer, review_evidence_sha256; exact source_commit and binaries_sha256 map probe/cli/b2_probe; fuzzy_review (each candidate pair exactly once, actual review_ref and KEEP-TOGETHER or FALSE-POSITIVE-KEEP-TOGETHER); budget=BUDGET from the module; allow_fit=true only after actual owner approval, allow_distribution=false, blind=false. All 48 known classes must be in train; dev and test must each contain supported records. Preserve candidate and lock immutable. Do not treat a JSON file or shape check as proof of independent reviewer identity.

## Actual private comparator (only after the external lock/rights decision)

Build with testing enabled using the normal CMake toolchain on an approved development machine. `b2_pipeline_probe` exists only in the research build; there is no B2 option, arbitrary model loader or weights in the product CLI. The development transport sends a fixed bounded little-endian int16 weight matrix with a positive uint32 margin and input bytes over stdin to the probe. Native common extraction comes from the exact same pipeline as B0/B1. The classifier is an abstention guard, cannot create slots, change deterministic negative outcomes, introduce plan authority, execute utilities, or resolve unrecognized utterances. This intentionally caps B2 end-to-end recall at the common grammar; raw classifier intent recall is separate. No external model pack/training of neural models.

```sh
python3 -B tools/f1_compare.py \
  --seed /private/seed.json --rights /private/rights.json \
  --candidate /private/candidate.json --lock /private/lock.json \
  --probe build/release/tests/pipeline_probe --cli build/release/dictum \
  --b2-probe build/release/tests/b2_pipeline_probe --output /private/results.json
```

The runner rejects drift of the source, binary hashes, rights/candidate/split and review shape. It fits only supported train rows with native feature masks (never gold spans), 12 epochs and seed 20261124. Margin candidates 1/2/4/8/16/32 selected solely by dev supported exact outcomes, largest margin on a tie. Then B0/B1/B2 compare on exactly the same locked development test records. Full denominator counts timeouts and invalids as misses; no posthoc removals; incomplete dev run invalidates margin selection. Report raw intent and joint/resolved, coverage/selective accuracy, exact outcome counts by class/language, misses, cold process latency and weight hash. Report stays private; no persisted product weights. No actual independent effects oracle, JS/PSS/FES, reference VM warm/RSS or blind gate claim. Follow preregistration for actual reference VM and independent holdout at the separate approved stage. Keep corpus and output outside Git; return only aggregate sanitized counts and hashes. CI tests are mechanical shape/negative cases and fixed-weight native integration, not trained Dictum metrics.


## Ready-to-use author/reviewer packet

`tools/f1_collect.py` is an offline worksheet generator and assembler. It generates 300 **empty assignments** (5 per supported intent plus 20 each ambiguity/OOD/security; target 210 ID/90 EN). No LLM-authored utterances, labels or approvals. Share only assignments, author drafts and semantic-reference with human authors; do not share existing gold/grammar. Each author records actual language and original text, semantic group/family and pseudonym/source identity. Assignments are coverage targets, not required gold labels. Each source ID identifies one author and source version. Retain the original packet, including blank/skipped assignments.

```sh
python3 -B tools/f1_collect.py init --output /private/f1-author
python3 -B tools/f1_collect.py review-sheet --author /private/f1-author/author-drafts.json --output /private/review.json
python3 -B tools/f1_collect.py assemble --author /private/f1-author/author-drafts.json --review /private/review.json --output /private/f1-reviewed
```

Fill author drafts manually before making the review sheet. The reviewer independently reads the actual text, chooses exact expected label, typed values and byte-span provenance using the semantic reference, records actual pseudonym, decision ref, review evidence hash, sensitivity/adjudication and accept/reject reason. The reviewer must differ from the author. Do not feed native/model results to the labeler; the worksheet hides assignment intent hints. Preserve exact text. For rejected records leave gold fields null; skipped/rejected IDs remain in private audit. In `assemble`, every submitted row must be reviewed; accepted rows are validated against the contract and source identity, and output `seed.json` uses canonical bytes. A separate `rights-review-request.json` is explicitly HOLD with no approvals and is deliberately rejected by the actual rights validator. An owner must actually approve permitted source use after reviewing the exact seed and source digests; record that decision in a separate rights.json as described above. Never just flip a flag without actual authority. If coverage is incomplete, create a revised collection before locking, not after results. Final candidate preparation also checks fuzzy contamination and connected groups. No private raw text, IDs or worksheet content should be uploaded to GitHub. Keep the private workspace outside the repository. Tests use mechanical toy rows, not actual human contributions.
