# ADR 0006 — F1 candidate slot domains, not an implicit IR v1 extension

Ref #31 / #28. Keep the pinned v1 registry, profile, four IR schemas and old gold unchanged. The ten deferred occurrences in nine intents need explicit domain types. A standalone candidate-value schema v2 and domain contract now specify them, plus DNS record_type A and explicit provenance for its default. This does not make them accepted IR v1 types. Native ingestion, codegen/differential, provenance from exact input span/context, and new IR/catalog version compatibility remain separate gates. Do not cast a DNS name, literal text or package query to filename.

Initial fixture scope is deliberately narrow: exact authored allowlists, canonical lowercase DNS names without trailing dot, canonical documentation IPv4/IPv6 (no zone), literal text bounded by UTF-8 bytes, explicit first/last, package ID vs query, and utility/option pairing. No resolution, execution, host probes, regex compilation, raw text projection, command template or real target authority. A valid shape/domain does not imply semantic entailment, verified binding, or permission. DNS A only; other types cannot be silently mapped to A. Ping count remains IR v1 bounded <=4 and no traffic. Diagnosis remains narrative-only, never a plan/handler. Window limit 86400 seconds (24h) for service log, system errors and file search; half-open UTC, no future or invalid intervals, no implicit local-zone interpretation. This is a proposal bound, not proof of bounded host traversal.

Data-only oracle uses JSON Schema plus semantic rules and fixed independent authored positive/negative vectors. No human gold, native parity, target compatibility or actual runtime support claim. All real bindings remain BLOCKED/NOT VERIFIED. Integration requires versioned native IR and regression before activation.
