# B2 lightweight linear baseline — development mechanics

Ref #40 / #28 / #35. **Actual Dictum B2 fit and evaluation NOT RUN.** Corpus rights and independent human review are external prerequisites, not something a program or model may self-attest. No text corpus reader, weight serialization, product pack loader, or CLI B2 mode is added here.

The baseline mechanics are fixed: 48 canonical ordinal classes (index = ordinal minus one), 1024 binary feature bins, FNV-1a 32-bit hash of byte word runs, ASCII case folding only, punctuation separators (non-ASCII UTF-8 bytes retained as part of words), no Unicode linguistic normalization. Sorted nonoverlapping authoritative byte spans mask complete intersecting word runs; exact input UTF-8 and scalar boundaries required. Hash collisions and unknown language coverage are limitations, not semantic evidence. Native and Python implementations use binary features, int16 weights and bias, int64 exact accumulation, deterministic abstention on ties, empty features or inadequate positive integer margin. Margin is not a calibrated confidence. Numeric multiclass perceptron fitting is deterministic for a fixed input ordering, seed and epochs, saturates weights, and has bounded numeric rows/epochs. Only abstract hand-authored numeric rows are fitted in CI; fixed synthetic weight formulas exercise native parity, not trained Dictum weights.

The actual F1 comparator must use an independently reviewed, rights-approved private corpus with group-aware locked train/dev/test membership before fitting. No repository F0/F1/S2 regression vectors, blind labels, or test-derived thresholds may enter training.
