# Threat model v1 — DCT-005 / A5

Status: kontrak F0-A, bukan hasil penetration test atau security sign-off. Normatif baseline §5.1b, §9–9.5, F0 §2/3/5. Product F0–F4 proposal-only, executor F5 NO-GO; VM lab bukan product.

## Assets, actors dan boundaries

Assets: intent/slot literal dan provenance; context, catalog/policy/model snapshot dan trust anchor; target identity/root handles; preview dan audit; user consent; local secrets, credentials, host filesystem dan network; VM snapshots, CPU/RAM/FD/output budgets; research evidence/holdout. Actors: manusia pemilik/admin (berwenang memilih scope, bukan automatic root); local caller untrusted; Front/parser/model/retrieval (assume compromised); hostile file/log/catalog/pack/upstream util; other local same-UID process; trusted installer/authority and independent human approval (future); executor/lab controller; privileged host/operator. Kernel, firmware, hypervisor dan root attacker compromised di luar jaminan; snapshot rollback oleh host tidak dapat dibuktikan tanpa anchor eksternal. No claim universal safety.

F0–F4: single CLI proposal pipeline with bounded native metadata and trusted resolver/policy/compiler/renderer boundary. No route to spawn target/daemon, egress, broker or run; CLI run absent/unsupported. Native probe reads only approved fields, no arbitrary /proc, env, history, files, sockets or daemon proxy egress. Input/model/output untrusted; catalogue and model artifacts trusted only after verified immutable snapshot; development fixtures explicitly pinned separate trust. Do not mistake schema/ID/hash for authorization. Preview copied manually outside sandbox; terminal control/option injection and secrets remain blockers even without executor. No automatic clipboard/history.

F5 (future only): Front untrusted -> Broker authority with independent validation -> Trusted Approval endpoint directly to human -> Executor restricted to broker-issued consumed plan; no route Front->approval response/executor. Broker, approval UI/input path, executor, trusted installer, kernel primitives, verifier and privilege helper (if any) are TCB; Front and utility output not TCB. See ADR 0002. Separate UID/process/namespace/LSM proof required against compromised Front including ptrace, proc mem, /proc/pid/fd, terminal capture, signal, FD theft and same-UID injection. Peer credentials are identity evidence, not consent. If isolation or human path unprovable, F5 stays NO-GO.

## Security and residuals

READ is not safe; secret exposure, IPC, resource and network effects remain independent; unknown or HIGH deny. A3 all bindings BLOCKED and execute_eligible=false. Root class is not root handle. INFO must not spawn help/man/pager; native probes constrained. Redaction is not complete secret detection; where sensitivity/output cannot be established use non-copyable/deny. No promise of safe archive extraction, no arbitrary shell, no hidden agent loop. Host equivalence can conflict with isolation; do not open capability merely because namespace hides target. Seccomp filters syscalls, not filesystem paths; Landlock ABI and gaps in IPC/filesystem semantics need verification. cgroup alone does not authorize target or data. No single primitive is complete containment.

F5 precondition: per-capability reviewed evidence, 100% expected policy outcomes and zero observed unauthorized effects, no uncontained process or consent bypass, independent human EXT security review plus owner approval. F0-A self review + LLM-ADV and owner scope gate are not EXT. Executor-only obligations remain DEFERRED-BLOCKED, cannot block proposal-only research except if a flaw impacts preview/intent/policy/secret leakage. Tests not run remain NOT RUN, not PASS. Audit locally records event/action digest, outcome/reason, elapsed time, versions, no raw input/output or secrets by default. Threat register evolves by ADR/issue with immutable evidence, no baseline waiver.
